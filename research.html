ResearchOngoing

Keeping the codebase and the GDPR record of processing in sync

With Chouki Tibermacine and Mohammed Lamine Kerdoudi

The GDPR record of processing activities (Article 30) states what an organisation claims to do with personal data, but nothing guarantees that the code does the same: data collected for one purpose can silently be reused for another. We study an automated approach based on code annotations and static analysis to keep the record and the source code synchronised in both directions, detecting drift of the implementation from the record, and the reverse. The annotations are also explored as a way to drive other compliance features such as consent management, with validation on real cases and in CI/CD pipelines (a “DevPrivOps” perspective).

ResearchOngoing

Comparing large language models for secure code generation

With Chouki Tibermacine, Régis Fleurquin and Salah Sadou · IRISA, Université Bretagne Sud

LLMs improve developer productivity, but the code they generate may contain vulnerabilities such as SQL injection, weak cryptography or improper input validation. This work builds a benchmark of programming tasks with security pitfalls, generates code with open-source and commercial LLMs, and evaluates it with static-analysis tools (SonarQube, Bandit, Semgrep) against OWASP Top 10 and CWE criteria. Expected outcomes: a reusable evaluation framework, the recurring vulnerabilities per model, and recommendations (prompt engineering, post-processing filters) for AI-assisted development.

ResearchOngoing

Privacy impact of anti-cheat systems in video games

With Maxime Huyghe

Competitive games increasingly rely on anti-cheat software running at the most privileged level of the operating system (kernel, Ring 0). This work maps the architectures and intrusiveness of major solutions, builds a taxonomy of the data they collect, and measures the gap between what vendors declare and what is technically observed on a reproducible test bench. It also assesses the attack surface created by vulnerable anti-cheat drivers (Bring-Your-Own-Vulnerable-Driver attacks) and confronts these practices with the GDPR: minimisation, transparency, privacy by design and impact assessments.
